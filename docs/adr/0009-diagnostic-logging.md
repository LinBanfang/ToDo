# ADR-009: 诊断日志（零依赖本地日志）

## 状态
已采纳

## 背景
跨机器排查更新检查失败难：1.0.11 曾把一切失败原因吞掉、只显示 `MissingFieldException` 的晦涩文案，真实原因（防火墙/WFP 拦截、网络错误、源数据缺字段）无从得知；且应用是单机工具、无后端可上报日志。需要一个轻量、易读、写失败不影响主流程的本地诊断日志。

## 决策
- 自写 `Services/DiagnosticLog.cs` 静态类，**零第三方依赖**（不引 Serilog/NLog，符合项目"零外部依赖"风格）。
- 位置：`<exe>\logs\app.log`（`AppDomain.CurrentDomain.BaseDirectory`）；1 MB 轮转保留 2 份。
- 格式：`[时间戳(yyyy-MM-dd HH:mm:ss.fff)] [级别] [模块] 消息`，级别 INFO/WARN/ERROR；首期全量记录、不做级别过滤。
- 线程安全：`lock` 串行化（更新检查跑后台线程）；写失败静默（try/catch，目录不可写时降级，日志缺失不影响功能）。
- 脱敏：URL 含 `access_token=` 或 `user:pass@` 时打码，避免泄露私有 appcast 凭据。
- 首期接入 `UpdateService`：源列表（脱敏）、检查开始（启动/手动）、逐源结果（成功 version/zip 或真实异常）、检查结论。

## 后果
- 优点：跨机器取证容易（报错后看日志即知哪个源、什么原因）；定位拦截点（防火墙规则 / WFP / 安全软件驱动 / 代理）有据可查。
- 权衡：日志位于安装目录内，自动更新覆盖安装目录可能清掉旧日志（可接受，新版启动即重建）；首期无级别过滤与 UI 入口（按需再补）；`DiagnosticLog` 文件大小/轮转策略后续可调。
